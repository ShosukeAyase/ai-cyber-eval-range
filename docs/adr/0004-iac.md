# ADR 0004: Infrastructure as Code

- Status: Proposed
- Date: 2026-07-24

## Context

A declarative plan supports review, drift detection, reproducibility, and destroy operations. OpenTofu avoids coupling the design to a single vendor control plane.

## Decision

Use OpenTofu modules with pinned providers and plan-time policy checks. The model can propose changes but cannot run provider credentials or apply plans.

## Alternatives

- Terraform
- Pulumi
- Crossplane
- Ansible-only

## Security consequences

- Preserves the four-plane trust model and default-deny posture.
- Requires explicit negative tests and independent telemetry.
- Residual risk is recorded in the risk register rather than hidden by the technology choice.

## Operational consequences

- Requires pinned versions, lifecycle automation, health checks, capacity planning, and documented rollback.
- Increases initial implementation work in exchange for deterministic controls and reproducibility.

## Rejected options

Imperative or continuously reconciling systems may obscure destructive changes or enlarge Kubernetes control-plane risk for the initial release.

## Revisit conditions

Revisit for multi-cloud maturity, provider coverage, or approved organizational standards.
